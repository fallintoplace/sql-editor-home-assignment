# Workspace and editor direction

## Goal

Make ClickStudio feel like a focused ClickHouse development environment.

## Workspace

The workspace brings together:

- SQL tabs and saved files;
- schema exploration;
- query results;
- history;
- charts;
- EXPLAIN views;
- assistant context;
- documentation.

The user can move between these surfaces while staying anchored to the current SQL and execution evidence.

## Editor experience

The editor direction includes:

- statement-aware execution;
- formatting;
- validation;
- autocomplete;
- alias-aware column suggestions;
- snippets;
- query outline;
- command palette;
- quick navigation;
- recent locations;
- split views;
- checkpoints and restore.

## Context model

Workspace context can be layered into:

- connection context;
- schema context;
- document context;
- selected result context;
- reusable playbooks.

Showing these layers makes assistant behavior and advanced workflows easy to understand.

## Product direction

The editor can continue growing around ClickHouse-specific workflows such as:

- plan inspection;
- performance comparison;
- schema navigation;
- reusable query patterns;
- result-driven child queries;
- documentation lookup.

The aim is a compact environment where SQL remains the center of the experience.
